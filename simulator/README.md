# Симулятор «Қайда?» (поток H, ТЗ 14)

Реальных данных перевозчиков и заводов пока нет. Симулятор заполняет всю цепочку пути
отходов и ведёт машины в реальном времени. Он работает **только через публичное API**
от имени демо-аккаунтов: те же функции, права и RLS, что у приложения водителя, оператора,
жителя и акимата. Когда появятся настоящие водители, его просто не запускают, и в
приложении ничего менять не нужно.

## Одна команда → полные тестовые данные

```bash
export SUPABASE_URL=https://<ref>.supabase.co SUPABASE_ANON_KEY=<anon key>
npm run sim:all                   # очистка прошлой симуляции → сиды → история за 14 дней (~1–3 мин)
npm run sim:live                  # 5 машин в реальном времени (пульт — админка → «Симулятор»)
npm run sim:check                 # сводка дашборда и путь площадки
```

В облаке то же самое запускается кнопкой: **Actions → «Симулятор · данные и реальное время» → Run workflow**
(`command`: `all` / `history` / `live` / `purge` / `check`). Workflow использует переменные репозитория
`NEXT_PUBLIC_SUPABASE_URL` и `NEXT_PUBLIC_SUPABASE_ANON_KEY`. Каждую ночь в 00:30 по Астане он
дописывает историю за прошедший день, чтобы демо оставалось свежим.

На сервере нужны секреты функции `DEMO_MODE=true` и `DEMO_PASSWORD`. Локально, без запущенной
Edge Function, можно задать `SUPABASE_SERVICE_ROLE_KEY` и `DEMO_PASSWORD`: симулятор сделает то же, что `demo-login`.

## Что создаётся

**Сиды** (`data/astana.ts`, идемпотентно: id детерминированы, повторный запуск обновляет те же записи):

| Что | Сколько |
|---|---|
| Город / район | Астана / Есиль (граница района — полигон) |
| Контейнерные площадки | 25 на реальных улицах левобережья, по 2–4 контейнера (всего 74), QR `AST-S01…` |
| Объекты | сортировка, 2 переработчика (ПЭТ, макулатура), полигон, 3 пункта приёма — помечены «(тест)» |
| Перевозчики и машины | 2 перевозчика, 5 машин: 3 смешанных, пластик, бумага/стекло/металл по дням |
| Маршруты | на каждый день истории и на 3 дня вперёд |
| Аккаунты | `demo.admin.1`, `demo.akimat.1`, водители 1–5, операторы 1–3 (сортировка, переработчик ПЭТ, пункт приёма), 20 жителей с домами и согласиями |

Координаты площадок приблизительные, в пределах квартала. Уточнить их можно точкой на карте в админке.

**История** (`src/history.ts`), по дням:

* рейсы по маршрутам: трек по дорогам (OSRM, кэш в `data/routes-cache.json`), GPS-точка каждые 15 с,
  вывоз каждого контейнера с фото и оценкой, заполненность, загрязнение;
* приёмка на сортировке (брутто/тара/нетто) и итог по видам, сумма которого точно равна весу партии;
  ПЭТ уходит переработчику новой партией (`parent_output_id`), откуда флекс идёт покупателю;
* выход вторсырья из смешанных ТБО низкий (органика 35–40%, ПЭТ ~16%, бумага и картон ~11%,
  стекло ~9% состава), отсюда разрыв «заявлено / реально» на дашборде;
* жители: фото контейнеров и предметов, жалобы (на «грязных» площадках чаще), сдачи в пункте приёма
  с бонусами; акимат разбирает жалобы (в работу, подтверждено, отклонено).

**Нарушения** — заданная доля плюс скриптованные события для проверки флагов:

| Сценарий | Доля | Скриптовано | Что срабатывает |
|---|---|---|---|
| «Смешанная» машина забрала раздельный пластик | 12% рейсов | позавчера, машина v1 | `mixed_flag` у вывоза и рейса, нарушение перевозчика |
| Рейс уехал на полигон вместо сортировки | ~7% | 3 дня назад, машина v4 | `mixed_flag` + `deviation_flag` (geofence ≠ план) |
| «Грязные» площадки (Туран 37, Кабанбай батыра 43, Керей-Жанибек 14) | — | всегда | низкий рейтинг чистоты, больше жалоб |

**Реальное время** (`src/live.ts`): 5 машин едут по сегодняшним маршрутам и раз в 10 с отправляют пачку GPS
(`trip_add_positions` → Realtime `vehicle_positions` → карта). Скорость ×1 / ×10 / ×60. В пути они делают
вывозы, по приезде завершают рейс, после чего оператор принимает партию. Сценарии в live: v1 смешивает
пластик, v4 едет на полигон (выключить — `--no-events`).

Пульт — запись `app_settings.simulator`. Её меняют админка (вкладка «Симулятор»: запуск, пауза, сброс,
скорость) или команда `sim control --status paused --speed 60`.

## Фото

`photos/` — синтетические картинки с пометкой «TEST PHOTO». Оценки к ним генерируются в формате ответа
`/ai/analyze` (`model_version: sim-synthetic-0.1`, рамки посчитаны по формуле загрязнения ТЗ 6.3).
Когда команда снимет 30–50 фото контейнеров Астаны, их нужно положить в `photos/` под теми же именами.

## Команды

```
node --experimental-strip-types src/cli.ts all      [--days 14] [--seed 42]
                                         seed     [--days 14] [--ahead 3]
                                         history  [--days 14]
                                         live     [--speed 10] [--minutes 60] [--no-events]
                                         control  --status running|paused|reset|stopped [--speed 1|10|60]
                                         purge                 # удалить симулированные данные (справочники остаются)
                                         check
```

Переменные: `OSRM_URL` — свой сервер маршрутов; `OSRM_OFFLINE=1` — без OSRM (треки по кварталам).

## Проверки

* `npm test -w @kaida/simulator` — юнит-тесты: сумма итогов = весу, формула загрязнения, GPS, сценарии.
* CI, job «Симулятор · e2e»: поднимает пустой Supabase, запускает `all` только с anon key и проверяет
  критерии ТЗ 7 и 14 (`test/e2e_checks.sql`): путь до статуса 6, сумма кг, флаги, треки, цепочка
  партий, рейтинг чистоты. Затем повторный запуск, чтобы проверить идемпотентность.
