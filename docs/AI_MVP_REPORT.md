## 2. Модель

Готовая YOLO11n (Ultralytics, веса COCO) дообучена на наших 13 классах.
Быстрый режим: CPU-раннер GitHub Actions, 36 минут, 6 эпох, вход 416 px.

### Сравнение на одном тесте (403 настоящих фото)

Обе модели прогнаны кодом ИИ-сервиса (`app.detector`), классы переведены в наши 13.

| Показатель | Исходная YOLO11n (COCO) | Дообученная waste-yolo-0.1 |
|---|---|---|
| mAP50 по 11 классам, что есть в тесте | 0,019 | **0,365** |
| Правильный контейнер (фото с одним предметом, 322 шт.) | 10,6% | **74,2%** |
| Время на фото, CPU | 55 мс (640 px) | **24 мс** (416 px) |

Метрики Ultralytics на тесте: mAP50 **0,391**, mAP50-95 0,350, precision 0,48, recall 0,40.
Критерий ТЗ 6.4 «mAP50 ≥ 0,4» почти выполнен (0,391); «правильный контейнер ≥ 75%» — 74,2%.
Скорость на CPU: 49 мс p50 при критерии ≤ 3 с.

### Как улучшить дальше
- Полный режим того же workflow: `hours=3.5`, `imgsz=512`, `synth=1500` (≈ 4–5 ч на CPU).
- Добавить `--taco-unofficial` в сбор (+~3700 фото TACO).
- Добавить наборы Roboflow с тетрапаком, батарейками, органикой.
- Снять 30–50 фото Астаны и проверить `eval_astana.py`.

## 3. База упаковок по штрихкоду

- Таблицы `packages` (штрихкод → материал → класс ИИ → контейнер) и `package_scans`
  (кто, где, когда сканировал) — миграция 8; RPC `package_lookup(gtin)` и `package_scan(...)`.
- Стартовые данные — миграция 9 из парсера `db/packages/collect_packages.py`: **619 упаковок**,
  19 настоящих из Open Products Facts (в т. ч. казахстанские, префикс 487) и 600 синтетических
  EAN-13 с префиксом 487 по всем 13 классам (бренды выдуманы, `source = 'synthetic'`).
- Open Food Facts в этом прогоне не ответил (503/500 на все три способа запроса с раннеров
  GitHub), поэтому пищевых товаров пока нет. Парсер повторит попытку при следующем запуске.
- Баллы за сам скан не начисляются; правило `package_scan_reward` создано выключенным.
