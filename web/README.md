# /web — Қайда?: 3D-карта (поток D) и 3D-цех (поток E)

Next.js 15 + TypeScript + Tailwind. Здесь реализованы два модуля ТЗ: **§8 3D-карта** и **§9 3D-цех**.
Фронт работает на моках (`src/mocks`), пока бэкенд (поток A) не готов.

```bash
cd web
cp .env.example .env.local   # по умолчанию включены моки
npm install
npm run dev                  # http://localhost:3000  →  /map  и  /workshop
npm run build && npm start   # продакшен-сборка
```

## Маршруты

| URL | Что |
|---|---|
| `/map` | 3D-карта Астаны (MapLibre GL + deck.gl) |
| `/map?path=<siteId \| qr>` | сразу режим «Путь» для площадки (ссылка из экрана пути) |
| `/map?site=<id>` / `?facility=<id>` | открыть карточку объекта |
| `/workshop` | 3D-цех сортировки (react-three-fiber) |
| `/workshop?stage=optical` | подсветить «Ваша партия здесь» на этапе (`receiving, opening, trommel, magnet, optical, manual, baling, residue`) |
| `/workshop?facility=<id>&from=<siteId>` | переход из пути; кнопка «Показать на карте» вернёт обратно |

## 3D-карта (§8)

- **P0:** здания OSM, выдавленные по высоте (`fill-extrusion`), наклон до 60°, вращение, светлая/тёмная тема;
  площадки (кластеризация при отдалении + 3D-столбики при приближении), объекты (3D-башни с подписями),
  карточка по клику («Путь» / «Войти в цех»); машины — low-poly мусоровоз, **плавная интерполяция** между GPS-точками,
  цвет по типу отходов рейса, данные через `VehicleFeed` (мок или Supabase Realtime `vehicle_positions`);
  режим «Путь»: анимированная линия рейса от площадки до объекта и дальше по итогам (переработчик / покупатель /
  энергия / полигон), камера летит по маршруту, боковая панель со статусами 1–6 и итоговой диаграммой.
- **P1:** фильтры слоёв, цвет по чистоте (≥80 / 50–79 / <50), тепловая карта, слой жалоб, упрощённый мобильный вид
  (без 3D-моделей машин, меньший наклон).
- **Не сделано (P2):** временная шкала «проиграть день».

Если векторные тайлы недоступны (нет сети), карта переключается на пустую подложку — 3D-слои платформы продолжают работать.

## Модель города: здания, дороги, районы, полигоны (OSM)

Слой «Здания, дороги, районы (OSM)» строит город из данных OpenStreetMap и **не зависит от тайлов**:
`src/lib/osm/` (запросы Overpass → GeoJSON) и `src/components/map/osmLayers.ts` (отрисовка).
Грузится по ячейкам ~1,4 км в видимой области (с zoom ≥ 13), **по приоритету**:

1. магистрали и основные улицы → 2. ключевые здания (с названием, жилые комплексы, соцобъекты, коммерция,
промзоны, здания от 9 этажей) → 3. зоны: жилые кварталы, промзоны, **полигоны (`landuse=landfill`)**,
пункты приёма и переработки, очистные → 4. остальные улицы → 5. все остальные здания → 6. парки и вода.

Здания красятся по типу (жилые / общественные / коммерческие / промышленные / культовые), высота — из `height`
или `building:levels`, иначе по типу. Названия ЖК, кварталов и ключевых зданий подписываются.
Результат кэшируется (Cache API); при желании делается **офлайн-набор**:

```bash
cd web && npx tsx scripts/fetch-osm.ts                          # центр города (~71.33 51.04 71.53 51.20)
npx tsx scripts/fetch-osm.ts 71.25 50.98 71.65 51.30             # весь город (долго, без спешки)
```

Файлы ложатся в `public/data/astana/` — карта сама их подхватит (по `manifest.json`) и перестанет ходить в Overpass.
Свой Overpass: `NEXT_PUBLIC_OVERPASS_URL=https://…/api/interpreter` (можно списком через запятую).
Данные © участники OpenStreetMap (ODbL) — подпись выводится на карте.

**Наши объекты** (`models.ts`) — детальные 3D-модели вместо столбиков (с zoom ≥ 13): сортировочный комплекс
(цех, приёмка, бункеры, тюки), переработка, полигон (террасы, газоотводы, весовая), компостирование (валы),
RDF-установка (котёл, труба), пункты приёма; контейнерные площадки с цветными контейнерами (zoom ≥ 16).

**Проверено:** загрузчик, конвертер, скрипт и отрисовка — на синтетическом Overpass-сервере (не реальные данные).
Реальный Overpass из среды разработки недоступен, поэтому на настоящих данных Астаны слой не запускался:
объём, скорость и пробелы в разметке OSM нужно посмотреть у себя.

## 3D-цех (§9)

- **P0:** 8 этапов (приёмка → разрыв пакетов → барабанный грохот → магнит/вихретоковый → ИИ-камера и оптический
  сепаратор → ручной добор → пресс/склад → RDF/полигон), у каждого подпись и панель описания;
  свободная камера + кнопки перехода; **анимация потока** (пакеты вскрываются, предметы расходятся по бункерам
  по цвету материала); режим **«Экскурсия»** — автопролёт камеры по этапам.
- **P1:** панель цифр по объекту, «Ваша партия здесь».
- **Не сделано (P2):** видеопанель с рамками ИИ, цеха ПЭТ/вермикомпоста/биогаза.
- Модели **процедурные (low-poly из примитивов three.js)**, внешних ассетов нет — вес сцены ~0 МБ,
  лицензионных вопросов нет. Для замены на glTF/Draco из Blender: `useGLTF` (drei) в `src/components/workshop/Machines.tsx`,
  путь можно брать из `facilities.model_3d_url`.

## Структура

```
src/lib/contracts.ts        типы ответов API (§3, §4, §7) — сверить с OpenAPI потока A
src/lib/api.ts              fetchMapObjects / fetchSitePath (моки ↔ реальный REST по NEXT_PUBLIC_API_URL)
src/lib/vehicleFeed.ts      MockVehicleFeed и SupabaseVehicleFeed (Realtime)
src/lib/routing.ts          OSRM (треки по дорогам) + фолбэк
src/lib/i18n.ts, messages/  ru (P0) и kk (P1); весь текст — через t()
src/mocks/                  сиды Астаны: площадки, объекты, машины, жалобы, путь
src/components/map/         MapView, Panels, truckMesh
src/components/workshop/    сцена, станки, поток предметов, камера
```

## Что подключить, когда готов бэкенд

1. `NEXT_PUBLIC_USE_MOCKS=false`, `NEXT_PUBLIC_API_URL`, ключи Supabase.
2. `GET /map/objects?bbox=` и `GET /sites/{id}/path?period=7d` должны вернуть форму из `contracts.ts`
   (координаты `[lon, lat]`; `track` — массив `[lon, lat]`).
3. Realtime `vehicle_positions`: в payload нужны `lon`/`lat` (или GeoJSON в `location`).
4. Мок-адреса и координаты площадок в `src/mocks/astana.ts` — плейсхолдеры; реальные приходят из сидов потока H.

## Проверено

`tsc --noEmit` и `next build` проходят; сцены отрисованы в headless Chromium (swiftshader).
Не измерено: FPS на ноутбуке при 5–10 машинах (в песочнице нет GPU) и загрузка реальных OSM-тайлов (нет доступа в сеть).
В dev-режиме drei `<Html>` пишет в консоль предупреждение React про unmount root — в продакшен-сборке его нет.
